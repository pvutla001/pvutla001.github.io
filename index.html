AUTOMATION PLANNING

Before you automate

  1. Describe the current process and the problem in plain language.
  2. Identify the owner, inputs, outputs, and boundaries.
  3. Separate discovery from actions that make changes.
  4. Decide how the operator will validate success and handle failure.
  5. Document the smallest useful first version.
TROUBLESHOOTING

Leave evidence, then leave a trail

  1. Capture the symptom, affected resource, user, and time.
  2. Record what is known and what remains an assumption.
  3. Test one hypothesis at a time and record the outcome.
  4. Verify the result from the affected user's perspective.
  5. Write the resolution so another person can repeat the reasoning.
